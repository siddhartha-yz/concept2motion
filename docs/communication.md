# 先讲清楚，再验证实现

用户看过六轮样片后反馈：看不懂视频想表达什么。这是目标失败，不能用数值正确、没有重叠或模型审看通过来否定。此前的 4/6 与 6/6 只描述旧的机器检查及 brief 辅助审看标准，不是观众理解率。

## 从参考中借鉴什么

参考：[abstract-algebra-promo](https://github.com/AnctyEnly453/abstract-algebra-promo)，固定提交 `5d01a758af8b4b3b7bb5a2a5b7f0efb4cf1667eb`。本地源码放在忽略的 `work/`，不改动、不把作品源码搬进基础设施。源码和实际关键帧共同支持以下观察：

- 26 秒先让雪花旋转；31 秒演示翻折；37 秒引出保持形状的十二种动作；42 秒才命名这种结构。具体对象、操作、归纳和名称依次出现。
- 52 秒用时钟展示 9 点加 5 小时的结果。符号和字幕指向同一个可见操作，不让观众先猜圆圈和数字代表什么。
- 字幕说一句话，画面演示这句话。章节标题帮助定位；雪花动作的环形排列进入下一章的钟面，转场承接已有对象。
- 这是宣传片，并非每个章节都完成概念教学。光效、音乐和镜头营造吸引力，但不能把其观众理解效果当作已验证事实。

本次实际渲染了 11 个时间点：7、26、31、37、42、52、60、78、125、188、248 秒；没有完整逐帧导出或完整听看成片。本机 Canvas/WebGL 初始化成功，页面无 JS 错误，Google 字体有加载成功记录；缺少音频文件，因此这次检视没有配乐。采样图片留在本地 `outputs/reference-algebra/`。首轮采样在页面就绪处超时，换成本机验证过的 GL 配置后采样成功，未定位首轮超时原因；不把环境失败当成参考作品失败。

## 解释模式的最小要求

固定输入必须说明受众、观众的问题、最终能复述的答案、每种对象的含义。当前实验只增加一个 32 秒 Softmax brief，不修改旧 12 秒基线或已有渲染证据。

先用单独一次官方 CLI 调用生成分镜 JSON。每个阶段写明时间区间、中文因果字幕、可见操作和预期观众推论，之后才生成代码。结构检查要求阶段完整、时间连续、每步至少三秒；这些检查不证明分镜讲得好。模型输出的分镜保留哈希，续跑复用；代码修订仍使用原分镜，改变教学目标须另起实验。

源码需实现已保存的分镜。每次演示尽量只引入一个新关系；数字和公式晚于对象含义。几何改变单位时明确说明；结尾留出答案和静止阅读时间。音乐和装饰属于后续表现层，不能补偿叙事缺失。

关键帧按每个分镜阶段的开头、中间、结尾采样。仍执行既有数值、几何、布局、像素与完整视频检查。采样覆盖计划时间点，不保证连续运动的可理解性，也不保证实际画面遵守了分镜语义。

## 让裁判先复述，而不是先读答案

解释模式的审看者只收到受众描述和按时间排序的图片；不收到作者 brief、目标答案、分镜、源码或“机器检查通过”的提示。它先返回 `reconstructed_message` 和 `causal_explanation`，再指出时间戳证据并给出修改意见。不能靠已有数学知识脑补缺失的解释，不能仅凭辨认出公式名称就判通过。

这只是相同模型家族的新上下文对静态图的盲复述。它可能知道 Softmax、读到字幕后过度推断，或对观众能力估计错误；机器不能凭复述的非空字符串证明答案与目标一致。AI 通过仍须标为待用户判断。人的反馈优先于 AI verdict。未来可对缺少问题、打乱步骤和仅有正确公式的候选做对照，再开展真实受众复述测试。

## 运行一条解释实验

```bash
python3 tools/batch.py run --out runs/explanation-softmax \
  --briefs benchmarks/explanation-cases.json --cases softmax --trials 1
```

沿用 [批处理配置](batch-workflow.md) 和已登录的官方 CLI。计数必须包含分镜调用。保留初稿、所有失败、修改指令、调用用量及完整视频；修订上限不变。不要把单条新样片的 AI verdict 报成“讲解问题已解决”。
