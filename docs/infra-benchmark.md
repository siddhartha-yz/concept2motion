# 一个能否证明 infra 有价值的短对照

此前模型审看通过、用户拒绝的样片是失败证据。新的检验目标是：同一任务下，基础设施能否减少生成和修订的等待，保留局部性，并产生值得继续看的运动。技术通过、AI 能复述、模型评分都不能代替用户的艺术判断。本文件是执行协议；没有实测记录时不声称已实现提速或质量改善。

## 冻结一个 10 秒问题

输入是 [infra-brief.json](../benchmarks/infra-brief.json)：六瓣雪花先转 60°，再转 60°，以原轮廓重合显出两个动作合成 120° 的关系。只讲这个实例，不在 10 秒讲完群的定义。

参考仓库固定为 [`5d01a758af8b4b3b7bb5a2a5b7f0efb4cf1667eb`](https://github.com/AnctyEnly453/abstract-algebra-promo/tree/5d01a758af8b4b3b7bb5a2a5b7f0efb4cf1667eb)。雪花段源码以连续物体、固定参照、旋转和停顿呈现操作关系。观看参考的连续播放后再记录观察，不能把读源码或抽帧写成已观看视频。它没有再许可声明；本实验参考呈现方法，独立写代码和几何，不复制成片或上游资产。

## 两个公平的作者入口

| 项目 | Direct | Infra |
| --- | --- | --- |
| 用户输入 | 同一冻结 brief 和视觉方向 | 同一冻结 brief 和视觉方向 |
| 作者输出 | 独立 ES module，最小显式时间绘制接口 | 短场景规格/局部逻辑，使用冻结的运行时 API |
| 公共契约 | 分辨率、时长、离线资源、render(t) | 相同公共契约 |
| 作者可获得的实现 | 不提供 infra runtime 或其示例源码 | 提供 runtime API 和可复用资产清单 |
| 预览与比较 | 相同预览设置、机器、采样方法和播放器 | 相同预览设置、机器、采样方法和播放器 |
| 修改要求 | 同一 `shared_revision`，允许精确小补丁 | 同一 `shared_revision`，允许精确小补丁 |

Direct 允许正常设计自己的 helper；不要故意给 Direct 糟糕提示词、强制重写整文件或降低预览质量。Infra 的新增便利就是实验处理，其他条件应一致。两臂都只收到最小契约及各自必需 API，不塞历史作品、拒绝记录、审看者答案或预期胜者。设计 API 文档不是生成第二套教学长文。

正式比较使用用户已登录的官方 CLI、相同配置模型与 reasoning effort、独立新上下文、无额外工具调用；本轮计划双方同用配置模型、reasoning `low`，这一覆盖必须入 manifest，而不是声称完全沿用全局配置。记录实际模型字段可得范围，不虚构服务端版本固定。当前协作 subagent 的候选若不是同一 CLI 配置，标为探索演示，不能纳入 same-model 对照。不要读取或转换登录令牌。

本轮接口是 ES module `scene.mjs` 导出 `createScene`：Direct 接收 canvas 并自行实现绘制；Infra 接收 `rt`，使用 `rt.scene`、`rt.snowflake`、`f.draw`、`f.caption`，也保留原始绘图扩展。完整返回值及时间契约以执行前冻结的 `runtime/API.md` 为准。两臂由 loader 适配成同一显式时间预览入口；不能把 Direct 强塞进旧证据协议或复制一份 Infra 实现给它。

先做一对，先检查协议和实际播放。若值得继续，再做三对，并预先确定 Direct/Infra 交替顺序；报告每次结果，不仅选赢家。运行前记录 API、runtime、brief 和提示词哈希。源码、补丁及可分享元数据入 Git；视频、依赖、原始 provider 日志留在 ignored 目录。

## 短预算与真正的 motion review

首轮每次模型调用上限 120 秒，每臂至多三次调用（初稿、公共局部修订、一次必要恢复），每对总墙钟上限 10 分钟，预览目标每版 15 秒以内。目标必须与实测区分；达不到就记失败，不把阈值改成耗时后的新目标。作者、修订和必要技术恢复累计共享预算；失败调用的耗时不能从表中消失。

先生成三张关键帧只用于尽早否决方向，随后必须观看完整 10 秒连续运动。两臂默认 960×540、24 fps 的草稿设置，保存真实视频及逐帧 t；12 fps 草稿不足以判断细腻运动。对 60° 起止、两次动作连接和最终重合附近加密抽帧，以辅助定位，抽帧不能代替连续观看。先验证媒体可播放、完整解码、帧数与时长，再审看；最终接受前才花完整 1080p 导出成本。

首次初稿和相同局部修订后各保留一次预览。审看者先只看匿名 A/B 视频，不读 brief、作者分镜或源代码，回答物体、动作、关系三个问题并给时间点；随后再看目标以定位偏差。AI 复述和缺陷定位是修订信息，质量比较保留为用户待判断。AI 不能投票决定自己作品更好，也不能用分数累加让循环继续。

## 从证据到一次局部修订

公共修改票据在运行前已写入 brief：第二次旋转从 5.2–7.2 秒提前到 4.85–6.85 秒，保持 2 秒动作和 10 秒总长，仅同步依附动作的标记。它检验修改局部性，不宣称改完更好。

票据绑定 base source hash、动作 ID、时间窗、可改字段和必须保留内容。补丁先在新版本目录验证，再预览；哈希或唯一匹配失败就拒绝应用，旧版仍可播放。不匹配时要求作者读取当前版本再修补，不能偷偷全量重写。对运行时规格优先改动作 ID 的起止时间；对直接源码也允许同等精确补丁。

除了文本 diff，比较修改前后的运动：0–4.85 秒应保持一致；本例新旧运动均在 7.2 秒完成，此后应一致（允许已冻结的确定性容差）。未改区间截图差异、几何变化、字幕改字或无关镜头变化都记为漂移。diff 行数不能独自证明局部性，时间语义也要检查。

真正的审看缺陷票据必须同时包含“发生在何时、画面证据、希望看到什么、允许改哪里”。最多追加一次视觉修订；若仍看不懂、方向被用户拒绝、或连续两版出现无关漂移，停止并标记 `rejected`/`budget_exhausted`，保留所有失败候选。技术故障最多一次恢复，在共享预算内执行；不能把艺术拒绝包装为技术故障继续循环。停止后允许另开新的视觉假设，但它是新实验，不能冲掉旧失败率。

## 硬约束保护机制，保留设计自由

机械检查限制时长、显式时间重绘、离线依赖、六阶旋转几何、两个角度端点及源码完整性。独立数学校验以旋转矩阵检查六个尖点集合在 60°、120° 后重合；模型返回的角度标签只是仪器读数，不能证明像素真的这样转动。连续画面验证真正可跟踪的运动。

不把“所有文字与所有图形永远不许相交”写成通用规则；字幕叠在雪花、残影层叠、光晕和箭头经过物体可能是设计的一部分。只对作者声明的可读字幕区检查越界和遮挡，并保留视觉审看。允许运镜、景深感和风格选择；对本来对称的雪花，不能加永久单色标记破坏轮廓对称又声称形状未变。必要的跟踪高光应是明确的演示覆盖层，不能改变所断言的物体。

旧 `render_scene.mjs` 的数学证据目前仅支持 Softmax/residual。本 brief 不能假称在旧验证器上通过；新 symmetry 检查与渲染适配必须明确记录，或者标为 `math_not_implemented`。安装成功、模拟工作流、真实模型生成、真实渲染、数学验证、连续运动审看和用户艺术判断各自独立报告。

## 记录一张不藏成本的表

每版记录 `trial_id / arm / attempt / input_hash / runtime_hash / source_hash / base_hash / status`，以及：

| 指标 | 计时/计量边界 |
| --- | --- |
| 作者与修订耗时 | 从官方 CLI 子进程启动到可用输出落盘；列全部重试和超时 |
| 模型用量 | 真实 usage 字段；cached/reasoning 是子集，不能重复相加 |
| 输出大小 | 模型完整输出字节与候选源码/规格字节分别列出 |
| 依赖成本 | Infra runtime、资产字节及人工设计时间单列；同时列完整可播放包大小 |
| 预览耗时 | 从渲染子进程启动到可用 MP4、检查结果落盘，包括浏览器启动 |
| 到首次可判断 | 输入提交到第一版连续预览可播放的总墙钟 |
| 一次局部修订 | 票据到第二版预览可播放的墙钟、补丁字节、文件数、changed lines、修改时间窗 |
| 恢复 | 原因、恢复次数与耗时、是否复用既有生成/预览、是否额外模型调用 |
| 人工介入 | 作者源码手改、额外提示、人工挑选、票据改写次数；infra 准备工作另列 |
| 视觉结论 | 用户盲看选择/拒绝/无差异；AI 复述及带时间点缺陷单独列 |

报告原始逐次值，三对以上再列中位数与范围；样本不够不推总体成功率。未经模型的补丁应用耗时与已有素材预览不能称为新场景生成提速。Infra 复用后的边际时间应连同首次 setup 成本呈现，不能只拿短 JSON 字节数对比包含运行时的独立源码。

只有用户觉得画面值得继续看、局部修改不漂移、总体等待确实下降，才有依据扩到另一个概念。否则下一步调整运行时表达力或视觉构造方法，避免扩成更大的 agent 平台。

## 首轮实测及后续变更

[两臂真实生成结果](../evaluation/2026-10-02/infra-pair-v1/REPORT.md)未显示端到端提速；4次调用、4条预览，总194.332秒。源码均由官方CLI独立生成，未手改。

其后新增命名动作 timing.json 和 retime.py；[参数实验](../evaluation/2026-10-02/timing-bindings-v1/REPORT.md)明确记一次源码适配和零新模型调用。该实验不是同模型生成的第二对，不用于艺术优胜或总体生成速度结论。

执行入口：python3 tools/iterate.py --run runs/new-pair；环境与预览API见 runtime-loop.md。每臂模型与渲染共享300秒，单次模型最多120秒；studio单job最多60秒。原始首轮执行器快照保留在报告目录，新版本支持哈希复用与单独的参数路径，不能把两版配置混写成同一实验。
