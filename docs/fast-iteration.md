# 快速否决方向，避免昂贵返工

用户明确拒绝中文 Softmax 样片，也指出实验迭代过慢。该轮成功的整段源码生成耗时 477.019 秒，完整渲染 46.79 秒，另有一次 600 秒超时。主要浪费在整份生成与晚发现方向错误，不能只优化编码速度。

本文保留前一版工具的记录。新的常驻 24 fps 预览、命名动作与实测入口见 [runtime-loop.md](runtime-loop.md)。首轮运行时生成并未证明提速；随后参数修订避开模型与绘图源码重写，分别记在新报告中。

后续局部修改应复用已有场景：当前会话产出短补丁、验证源码版本、快速预览，再判断方向。批处理的全新场景生成仍返回整份源码；它尚未接入补丁模型输出，也没有测量新场景的生成提速。停止用旧批处理的整份重输来做交互式局部试错。

## 小补丁

```bash
python3 tools/apply_edit.py --scene path/to/source \
  --patch work/edit.json --out work/version-02
```

`edit.json` 格式如下，哈希取当前文件的 SHA-256：

```json
{"files":[{"path":"scene.js","sha256":"CURRENT_FILE_SHA256","edits":[
  {"old":"the exact old text","new":"replacement text"}
]}]}
```

只修改已有文本资源；每个匹配必须非空且唯一，哈希不一致则拒绝，所有修改先验证再写新目录。旧版本保留，`revision.json` 记录补丁及前后哈希。不覆盖场景、不在补丁工具里启动模型或执行生成代码。数值或画面变化仍需重新检查。

## 草稿预览

```bash
node tools/render_scene.mjs --preview \
  --scene work/version-02/index.html --brief path/to/brief.json \
  --samples 3,9,15,21.5,28.5 --out runs/draft-02
```

沿用场景渲染的本机依赖配置。以原始画布渲染后缩放到宽 960 像素、12 fps，快速编码，保留源码快照、抽样检查、预览时间点检查和视频信息。结果标记 `preview_ready`，不会获得 `render_passed`，已有审看策略拒绝将其作为完整验证视频。低帧率不足以评价最终运动质量。

用已被拒绝的 32 秒素材实际验证：完整预览为 960×540、12 fps、384 帧，13.198 秒完成，视频全片解码通过。原完整视频为 1920×1080、60 fps、1,920 帧，46.79 秒。两次渲染的工具版本不同，是操作耗时对比，不是严格性能基准，更不是画面质量改善。

一次仅修改背景色字面量的工具测试：补丁 186 字节，源 JS 12,708 字节，本地校验与应用约 0.0006 秒。此项只验证编辑操作，不含模型生成补丁、浏览器启动或渲染；该一字符改动没有被当作新的艺术候选。两项速度测试均没有模型调用。

画面方向的下一轮先做三张关键帧，再做 5–8 秒运动草稿。方向获得认可后再追加教学内容和完整技术验证。当前作品仍被拒绝，快工具本身不证明视觉方向正确。
