# Concept2Motion 的定位、约束和验证方式

状态：**定位已明确，核心效果假设待验证。** 本文区分目标、已实现能力与待实现能力，不把设计目标写成实测成果。

## 我们要交付什么

**让 AI 把概念做成动画后，能够根据画面证据快速、局部地修改，并检验修改是否改善概念表达。**

输入是概念、受众和希望表达的关系；输出是可播放动画，以及可继续修改的源码、对象与时间信息、检查结果和版本记录。仓库提供生成、渲染、检查、修改和验证之间的接口。具体成片放在独立作品仓库。

当前先研究数学和机器学习概念。独立数学画面检查主要支持三分量 Softmax 与残差相加；另有特定的十秒旋转对称实验。支持这些实例，不代表已支持任意概念，也不代表已有通用教学正确性证明。

最终目标是减少达到可接受作品所需的模型调用、等待和人工介入，同时保持或提高表达质量。当前已有确定性渲染、局部补丁、部分数学检查和快速预览；可信评分与画面评价驱动的完整修改闭环仍是待解决问题。

## 仓库的约束在哪里

约束应保护概念关系、版本和修改范围，给 AI 留出布局、风格和表达方式的选择。硬性机制要求必须来自具体任务；不能把某一种排版偏好普遍当作数学真理。

| 约束 | 实施方式与当前边界 |
|---|---|
| 概念对应的数值和关系 | 从保存的输入重新计算。例如概率使用共同分母，残差输出逐项相加。当前只覆盖明确实现的任务 |
| 实际图形与声明一致 | 绘图接口记录长度、端点和进度，独立检查器核对，并抽查像素；直接绘图、遮盖和未采样区域仍有盲区 |
| 时间可以复现 | 用指定时刻的 render(t) 生成帧，保存工具、源码和采样时刻；可复现范围受环境版本影响 |
| 修改有边界 | 补丁绑定基础源码哈希，写入新版本，拒绝过期或不唯一的匹配；已有工具不意味着所有作者流程都已采用局部补丁 |
| 修改不能随意破坏其他内容 | 特定时序实验已检查保护区间；通用场景的保护对象、允许变化和退化检测仍需按任务实现 |
| 失败和成本可追查 | 记录所有版本、请求失败、渲染失败、模型用量和耗时；调用预算在运行前固定，完成的失败不能从报告消失 |

目前的数学时间接口也要求阶段顺序和稳定停留时间。这是有限实验的协议约束，不是所有优秀动画必须遵守的创作规则。若它限制了有效表达，应建立新协议做对照，保留旧结果。

## 我们依赖哪些假设

| 待验证假设 | 为什么可能有效 | 什么结果说明它没有成立 |
|---|---|---|
| 有依据的机制检查能减少错误表达 | 给作者提供具体的数值或图形缺陷 | 技术错误减少，但概念表达没有改善；或检查频繁误拒绝正确设计 |
| 有定位的反馈能提高修订效率 | 把模糊评价转成可执行、可验证的小修改 | 同预算下不优于普通自查，或经常破坏其他部分 |
| 复用渲染环境和局部修改能缩短整个循环 | 减少启动、重绘和整份代码重输 | 本地预览变快，但从 brief 到可接受结果的总耗时没有减少 |
| 这些能力能跨概念复用 | 接口与验证方法可以迁移到不同表达任务 | 收益只存在于调试过的两种题目，换概念就消失 |

还有两个前提需要独立核验：所选评价确实接近我们关心的表达质量；检查反馈确实来自画面，而不只是作者填入的正确数值。论文里的验证不会自动随更换裁判、输入形式或任务迁移过来。

## 如何保证准确性

**现在无法保证任意生成动画都准确。能做的是明确检查范围、发现错误并保留无法核验的部分。**

1. 数值层：从固定输入独立重算，明确公式、容差和支持的数值范围；超出范围拒绝或标记不支持。
2. 图形层：核对实际绘图几何、进度和可见性，附像素核验覆盖范围。正确的数值标签不能代替正确图形，稀疏像素检查不是整幅画面的证明。
3. 表达层：用选定且经过核验的评价方案检查目标关系是否被表达。抽帧判断不能证明未看的连续运动或真实观众学习效果。
4. 工具层：用事先知道对错的正负样本、数值边界和错误元数据检查误报与漏报，保留检查器自己的错误。

“检查通过”必须带上具体范围。渲染成功、数学通过、表达评价通过分别报告；未实现或无法核验的部分不能默认正确。

## 怎样证明工具提升了性能

**提升是实验结果，不是基础设施可以预先保证的承诺。** 这里的性能包括表达质量、可靠性、总成本与迭代速度，不能只报其中一个漂亮数字。

每轮实验前确定主目标、评价方案和判断提升所需的幅度。目标可以是同预算下质量更高，或质量达到预先规定要求时总耗时更低；阈值不能看完结果再定。评分问题尚未解决，所以这些阈值目前也尚未选定。

需要区分三种对照：

- **完整工具的价值**：同一弱模型、同一任务和输入，普通生成修订与使用本仓库的完整循环比较。普通组允许正常使用 helper、自查、运行错误和同等预览条件。
- **某个组件的价值**：双方使用相同基础工具，只开关检查反馈、局部修改或复用环境中的一项。最新 B/C 实验只测检查反馈，不能代表完整 infra 的效果。
- **能力差距是否缩小**：增加强模型普通生成作为参照，在同一评价上比较。接近这个参照也只说明该固定任务集的结果，不能宣布小模型获得普遍能力提升。

作者、反馈评审、修订和最终评测的调用与耗时都要记录；相同调用次数不等于相同 token 成本。保留所有任务和失败，使用未参与调试的不同概念，以任务为单位报告配对差异和不确定性。重复评同一视频或交换左右顺序不能当作新增独立任务。

若研究速度，报告从输入到可判断初稿、从反馈到修订结果、以及达到预先规定质量目标的总耗时；没达到目标的任务报告预算耗尽。若研究质量，按事先固定的评价比较并附导出率、裁判一致性和成本。不把程序通过率直接叫作作品质量。

## 目前证据支持到哪里

- 最新四组配对中，工具反馈和普通自查各赢一组、一组未决、一组缺视频：尚未证明稳定的表达质量收益。
- 同一个两秒片段的八组测速，复用环境的预览中位数约 0.53 秒，重新启动约 0.86 秒：支持局部渲染提速，不证明生成或完整创作提速。
- 工程正负控制验证了部分检查器行为：不证明任意画面正确，也不证明裁判或观众理解可靠。
