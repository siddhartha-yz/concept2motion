# Softmax 第一条实际闭环 · 2026-10-01

结果：**检查确实找到了真实画面问题，局部修订后通过；固定源码可以在两个独立浏览器进程中输出完全一致的视频。**

本次由当前 Codex 桌面会话完成创作与审看，没有运行额外代理或调用上游模型 API。作者和审看者是同一会话；这是可复现的工程试验，还不能证明盲评效果、模型生成稳定性或完全无人值守能力。

## 做了什么

从前一轮固定测试片缺少 exp / 共享分母语义线索的发现出发，编写了一份新的 Canvas2D 候选。它沿用相同 Softmax 输入 `[-1, 0.6, 1.8]` 和三种类别身份，呈现有符号 logits → 正指数质量 → 共享总量 8.24 → 总和为 1 的比例分区。这个新候选不用于对 Manim 与 Canvas 作公平效果排名。

新增本地工具把这条流程落到文件：源码快照 → 固定时间渲染 → 机制和画面检查 → 关键帧 → 带时间戳的审看 → 有预算的修订记录。场景与渲染器通过 [版本 1 协议](../../../docs/scene-protocol.md)衔接。当前只有 Softmax 的渲染证据验证器；其他案例显式报 unsupported。

## 第一版：真实失败

检查 53 个时间点，在 7 个采样帧中发现两类 `text_overlap`：

- 6.00–6.50 秒：旧类别标签 `z2` 与新说明同时占据同一行。
- 9.00–9.50 秒：总量 `8.24` 与新概率标签相撞。

已经查看 6.50 与 9.30 秒的实际关键帧，确认可见的重叠，并发现共享总量括号在几何体移动时过早出现。原稿与失败证据保留：[原始源码](v1-source/scene.js)、[检查记录](v1-checks.json)、[视觉审看](v1-review.json)。这不是为了演示检查器而人为注入的故障。

## 第二版：局部修订

只修改标注的时机：旧标签先退场，总量在堆叠完成后出现，概率和总和标签在归一化接近完成后出现。数学计算、类别颜色和矩形轨迹保持一致。导出预览的播放按钮也完成了小的事件循环修正。

两次完整导出耗时约 21.6 秒与 20.5 秒。视频 SHA-256 为 `db3ba5e47d34936a6f3a36ea653ef179092aca9cedc2b753fd03759bd364882f`。这是当前源码与当前运行环境的渲染复现结果，不是两次独立模型生成一致的证据。

已审看修订版的关键帧，确认两处原问题消失，以及有符号值、正质量、共享总量与最终概率分区之间的身份关系。[修订版检查](v2-checks.json)、[修订版审看与未解决事项](v2-review.json)、[结构化结果](results.json)。

## 能做到与还没做到

现在能保存失败、提供可定位的反馈、约束修订轮数、校验确定性输出，并把工程通过与用户艺术认可分开。工具不会把一次成功渲染或 AI 自评当作最终作品通过。

边界也很明确：检测框来自候选绘制时的测量记录，少量像素检查不等于独立验证全部画面；只查看了关键帧，不把这记录为完整实时观看；作者兼审看者，未做独立盲评；数学说明仍由少量符号辅助，没有证明纯几何的观众理解效果。模型用量与生成成本本轮未测。

下一步是把相同协议扩展到残差连接与 GRU，再对冻结 brief 做多次独立生成及独立审看。自动 CLI 编排、上游 VLM 原生管线和学习型记忆尚未验证。
