# 残差连接：第二条真实闭环

本次把 Softmax 使用的本地渲染、证据与修订流程复用到残差连接。当前 Codex 桌面会话编写原创 Canvas 源码，再用同一套工具实际渲染和审看；没有调用额外模型 API，没有新增代理。

## 机制与画面

冻结输入为 `x = [1, -0.5, 0.25]`、`F(x) = [0.2, 0.4, -0.1]`，独立参考输出为 `[1.2, -0.1, 0.15]`。F(x) 是手选示例，未声称存在训练后的网络或权重。

直通路径保持 x 的长度和正负方向；修正路径使用箭头。两条路径按颜色对应，在合并时首尾相接。最终结果另用明亮箭头表示：第二分量接近抵消但仍为负，第三分量因负修正而缩短。所有有向长度共用每单位 240 像素的比例尺。[分镜](../../../benchmarks/scenes/residual/STORYBOARD.md)、[最终源码](../../../benchmarks/scenes/residual/scene.js)。

独立验证器检查每个分量、直通恒等、输出相加、有向几何、最终首尾连接、关键阶段顺序、裁切、文字重叠及图形与文字碰撞。最终输出箭头的中心颜色从实际 Canvas 像素读取。

## 初稿缺陷与局部修订

初稿完成了真实 12 秒视频导出，早期数值和文字/文字检查通过。但补看 6.5 秒关键帧时，第一条直通色条遮住了合并说明。此时“render_passed”只代表当时的检查范围，不能等同于视觉通过。

保留了[原始源码](v1-source/scene.js)、[当时的检查](v1-full-checks.json)和[视觉修订请求](v1-full-review.json)。仅将合并说明的基线从 y=365 移到 y=315；数学、向量运动和动画时长不变。修订为一次视觉修改，技术修复为零。最终[检查](v2-checks.json)和[审看记录](v2-review.json)通过，艺术接受状态仍为 `pending_user_review`。

同时新增 `text_shape_overlap` 检查。用新检查器重新跑原始候选，抓到了 3 个碰撞时刻，保留为[真实回归失败证据](caption-regression-checks.json)。这不是故意注入的生成错误。

## 真正渲染与重复性

| 检查 | 结果 |
|---|---|
| 采样帧 | 53 帧，阶段顺序完整，修订版无发现 |
| 完整视频 | 1920×1080、60 fps、12.000 秒、720 帧 |
| 全帧机制与布局检查 | 720 帧通过 |
| FFmpeg 全片解码 | 通过 |
| 同一时间经过其他时间后重画 | 帧哈希相同 |
| 新浏览器重新导出同一源码 | 视频二进制 SHA-256 相同 |

最终视频哈希：`929ccdfaf908c6d3f3ed4e8bce18df14374baa61ff8b4a1f674548a0e51026f8`。第一次修订版渲染用时约 30.9 秒，重复渲染约 41.5 秒；重复任务与另一视频导出并行，这两个耗时不能作为性能比较。重复渲染验证同一环境下的执行稳定性，未再次生成源码。

## 像素检查的负例

另将[明确标记的回归脚本](../../../tests/fixtures/residual-pixel-overwrite.js)追加到修订版副本。脚本保留全部正确数值与几何证据，只把输出箭头中心画成品红色。

真实浏览器检查产生 45 条 `pixel_mismatch`，没有数值、几何或布局错误，退出码为 1。[检查证据](pixel-regression-v2-checks.json)。这验证了像素检查能发现此类画面/证据不一致；它不是生成试验，不纳入任何模型成功率。少量像素仍不能证明全部画面正确。

## Softmax 的后续回归

新增碰撞检查也抓到了旧 Softmax 在 8.5 与 8.75 秒的文字/色块重叠。实际关键帧确认分母展开文字落在移动的橙色色块上。[修订前源码](softmax-before/scene.js)、[新检查的失败证据](softmax-caption-sampled-checks.json)、[修订请求](softmax-caption-sampled-review.json)。

仅把该文字的淡入区间从 8.25–8.55 秒推迟到 9.15–9.45 秒。之后再次真实导出，全部 720 帧与视频验证通过；[检查](softmax-revised-checks.json)、[审看](softmax-revised-review.json)。原 Softmax 报告与哈希属于此前版本，保留为历史记录；当前基准源码采用此次修订。

## 能说明什么

两个机制案例已共享渲染器、证据协议、局部修订预算与审看记录。第二个案例暴露了检查缺口，形成了可自动重跑的失败样例，改善也反过来发现了第一个案例的问题。

当前仍是单次作者会话兼审看者，不是独立盲审，没有冻结 prompt 的多次独立模型生成，没有证明生成成功率或无人值守能力。订阅用量与费用未计量。没有使用用户的场景修改意见，最终审美接受仍归用户。GRU 仍只具有数值参考，不能报告渲染验证通过。

数值与边界证据由候选源码提供；实际像素采样覆盖输出中心，不能替代视觉审看或成为恶意候选的完整证明。局部浏览器进程与外部请求拦截也不是完整的不可信代码隔离方案。

源码、检查摘要与审看结论进入 Git；视频、帧、完整运行证据保存在本地 `runs/residual-loop` 及交付目录。最终工具还加入 renderer/validator 源码与哈希快照，后续新运行能追溯检查范围；本次较早的视频运行发生在此元数据功能加入之前，最终工具烟雾检查和 CI 会保存该快照。机器可读结果见 [results.json](results.json)。
