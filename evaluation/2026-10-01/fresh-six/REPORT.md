# 六次新上下文生成评测

冻结 Softmax 和残差连接的 brief，每个案例从三个新上下文生成原创源码。每个通过本地检查的候选再交给一个分开的新上下文审看关键帧。使用已登录 ChatGPT 的官方 Codex CLI，未向模型提供旧样片源码，也未提取登录信息或接入独立 API 密钥。

## 结果

| 案例 | 次数 | 初稿完整视频与机器检查 | 初稿审看 | 技术修复 | 视觉修订 | 最终结果 |
|---|---:|---|---|---:|---:|---|
| Softmax | 1 | 通过 | 通过 | 0 | 0 | 通过 |
| Softmax | 2 | 通过 | 修改 | 0 | 2 | 通过 |
| Softmax | 3 | 通过 | 修改 | 0 | 1 | 通过 |
| 残差 | 1 | 通过 | 通过 | 0 | 0 | 通过 |
| 残差 | 2 | 通过 | 通过 | 0 | 0 | 通过 |
| 残差 | 3 | 通过 | 通过 | 0 | 0 | 通过 |

按本次机器检查及 AI 采样帧审看标准，初稿接受为 **4/6**，最多两次视觉修订后的接受为 **6/6**。初稿均通过底层数值、几何、像素采样、阶段顺序、布局和视频检查；这不等于所有画面文字与动画叙事都正确。艺术接受仍为 `pending_user_review`。

共保存 9 个实际候选和视频，验证 6,480 帧。每条视频为 1920×1080、60 fps、12 秒，ffprobe 确认 720 帧且 FFmpeg 全片解码通过。六份初稿 JavaScript 哈希均不同。每次作者和审看调用的线程 ID 互不相同，共 18 个新上下文；事件记录中未发生命令、文件修改、MCP、网页搜索等模型工具调用。

没有人工修改候选源码或插入场景修订指令。这里的“人工介入为零”仅指六轮动画生成过程；搭建工具、监视运行和整理结果仍需要工作，不代表整个项目无需人。

## 保留的三次视觉修订

- **Softmax 2，第一次**：最终概率标签已经显示，但色块尚未填满标为 1 的容量。需要同步标签和几何完成时刻。[原版审看](softmax-02/attempt-01/review.json)、[第一次修改差异](softmax-02/attempt-02/revision.patch)。
- **Softmax 2，第二次**：单位转换缺少解释，概率总和已经显示为 1 后，另一条未标注的线仍在增长。需要明确除以同一个 S、解释重缩放，并固定总和指示。[审看](softmax-02/attempt-02/review.json)、[第二次修改差异](softmax-02/attempt-03/revision.patch)、[最终审看](softmax-02/attempt-03/review.json)。
- **Softmax 3**：显示的四位小数 `0.0446 + 0.2211 + 0.7342` 实际为 `0.9999`，展开式应写近似等号；归一化的精确容量仍可标为 1。[原版审看](softmax-03/attempt-01/review.json)、[修改差异](softmax-03/attempt-02/revision.patch)。底层计算采用未舍入值，未发现概率计算错误。

这些是独立上下文 AI 审看给出的意见，包含时间戳与实际帧文件名。它们可供人工复核，不能替代专家意见或最终审美判断。部分通过的审看也记录了局部箭头重叠和采样不足等保留意见。

## 执行入口与恢复

统一入口为 `tools/batch.py`，串起生成、真实渲染、检查、分开上下文审看和有预算的局部修订。每轮保留 brief、源码、分镜、源码快照、检查、关键帧、审看和调用用量。模型与渲染超时停止进程组；服务或协议故障保存进度后停止。

完成后实际执行了 `--resume`：六轮均跳过已完成状态，调用总数仍为 18，未新增模型调用。最终实现也检查已完成候选与渲染源码的完整性，相关测试拒绝人为改动的终态文件。状态恢复测试是 mock；上述六轮和完成后的续跑检查是真实运行，两者没有混计。

运行说明见 [batch-workflow.md](../../../docs/batch-workflow.md)。作者使用完整候选 JSON 进行局部修订，实际源码差异保存在各轮 `revision.patch`；它尚不是直接输出小补丁的模型接口。

## 用量与时间

18 次官方 CLI 调用，9 次作者调用、9 次审看调用。配置在运行前后均为 `gpt-6.1-sol` / `high`，未指定覆盖模型；服务内部模型版本没有固定。独立上下文不等于不同模型家族，也不保证统计独立。

CLI 报告输入 token 497,775，其中缓存输入 13,184；输出 token 72,287，其中推理输出 36,302。子项已包含在相应总项，不能再次相加。这些数值仅覆盖批处理的 18 次调用，不包含本聊天。未测量价格、订阅额度比例或现金费用。

串行调用耗时合计约 51.9 分钟，9 次本地渲染约 3.7 分钟。CLI 耗时包含客户端初始化、网络和推理，不能解释成纯模型推理速度。当前较重的完整源码生成、重输和多图片审看占主要成本，减少人工改图并未消除运行成本。

## 结论与下一步

这次小样本证明统一入口可以在两个已有机制契约上完成多次新源码生成、真实检查、独立上下文审看与有上限的修订。六轮不支持生产成功率或一般艺术质量的结论，也没有测试任意论文、完整网络、GRU 或其他渲染器。

最直接的改进应由这批失败推动：给单位与标签出现时刻增加契约，提供数值显示和近似等号格式化工具；让修订输出可验证的小补丁以减少整段代码重输；按实际阶段采样关键帧，覆盖当前固定八帧未必包含的转场。之后再扩展 GRU。

视觉审看只看静态采样帧，没有观看完整视频。注册证据由候选提供，像素验证仅覆盖指定中心点；这不是对恶意候选的完整证明。最终艺术接受归用户。

## 证据与版本

机器可读结果和调用用量见 [results.json](results.json)，固定输入见 [Softmax brief](brief-softmax.json) 与 [残差 brief](brief-residual.json)。各候选目录保存源码、检查、审看和渲染清单；视频、帧、完整运行目录及 provider 原始日志保留在本地，原始日志不进入 Git 或公开交付包。

本次在协调器源码快照、展示页和取消元数据完善之前启动；输入 prompt、协议、渲染器、验证器与审看策略当时已冻结。后续改进未改变任何候选或已有审看。最终协调器会额外冻结自身源码，旧运行记录保持原始检查范围。此项差异已记录在结果中，不能声称六轮运行的是最终协调器的逐字节相同版本。

## 后续用户反馈：表达目标仍未达成

用户观看后指出，最大的问题是看不懂生成的视频想表达什么，并提供了抽象代数宣传片作为参考。这是旧审看标准遗漏的核心失败。上述 6/6 仍是当时机器检查和模型审看的历史结果，不能视为用户接受或观众理解率。

后续实验增加明确受众、问题、对象含义、因果字幕、先于代码的教学分镜，以及不看作者 brief 的复述审看。参考分析与方法限制见 [communication.md](../../../docs/communication.md)。本次候选、分镜、检查和原审看记录保留原样。
