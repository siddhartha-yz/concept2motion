## 区别首先在画面机制

**对象与动作先成为画面的主体。**雪花章节中，镜头围绕一个大而明确的对象展开。旋转时，静止 ghost 轮廓和运动金色弧线让观众同时看见“原来在哪里”和“怎样移动”；翻折时，形状压扁到轴上再展开。最终形状相同这一事实由操作中的变化与终点共同表现。只看终点的静态图会误把它理解为始终未动。

**画面中的身份和位置沿时间接力。**实际检查的 46–49 秒显示：十二个动作图形缩小并回到同一环上的十二个时刻位置，下一场景从这些原位图形过渡到时钟数字。源码还包含雪花→片名粒子→雪花、有限域点云→二维码、E8→雪花回环。关键是两个镜头共享位置、对象映射或采样点，而不是各画一张图后交叉淡入。对应源码：[雪花与时钟](https://github.com/AnctyEnly453/abstract-algebra-promo/blob/5d01a758af8b4b3b7bb5a2a5b7f0efb4cf1667eb/promo.html#L554)。

**步骤用空间对应关系解释。**椭圆曲线段的实际序列依次出现 P/Q、金色直线、白色第三交点、粉色反射结果及垂直虚线。既有点仍然可见，后一个操作可对照前一步；后段轻微移动 P/Q 后，连接线和结果一起更新，揭示的是规则而非固定截图。这里的公式只是补充，几何才是机制。对应源码：[椭圆曲线](https://github.com/AnctyEnly453/abstract-algebra-promo/blob/5d01a758af8b4b3b7bb5a2a5b7f0efb4cf1667eb/promo.html#L1122)。

参考是宣传片，许多概念只做引入；不能据此声称观众理解了群论或密码学。它值得借鉴的是上述视觉组织能力，而不是把当前作品加上星空、金字和更多说明。

## 摄影、照明与节奏：哪些能力可以低成本复用

以下代码结论已与两段运动画面的表现对照，但不是完整成片的视听评分。

- 构图有明确主对象、尺寸和焦点；对称操作阶段主体居中，随后缩小移到左侧，为右侧运算表腾出空间。镜头移动幅度很小，通常 3.5–5% 的缓推或弧形缩放，避免相机抢走对象运动。
- 亮度层级由宽度不同的透明描边、additive glow、渐变背景和少量星层共同构成；统一后处理提供 bloom、暗角、细颗粒、冷暗暖亮分色。没有发现真正的景深或物理灯光系统，不能将其宣传为那些能力。
- `frame` 先画 scene+camera，再做后处理，最后画字幕和章节，文本保持锐度。二维码场景将 bloom 降为 0.3 并关闭色差，承认清晰度比统一炫光更重要。
- `BPM=90`；scene 的 start/len 是小节单位，操作、字幕、音效在统一局部秒时间上对齐。音效 cue sheet 是从场景导出的，音乐按相同小节分段编排；时钟步进及五度圈音符与对应动作共用时间值。本次没有实际听取生成音乐。

## 最小可实现能力

### 1. 可独立修改和复用的场景、对象、镜头

将模型通常反复重写的 HTML 外壳、随机种子、统一样式、时间调度留在 runtime；模型只改一个 scene 模块。最低入口：

```js
defineScene({ id, duration, draw(ctx, localTime), shots, camera, cues });
asset(id, buildGeometry);             // 一次构造，后续重复使用
object(id, geometry, poseAt);          // 身份稳定，时间决定位置/姿态
```

同一个 `localTime` 的状态和画面必须可反复求值；不能依赖先播放到某时刻才得到正确状态。跨镜头的 geometry/pose 映射要显式引用对象 ID，以便改一个镜头时不打断下一镜头。参考的 `SC`、`SNOWPTS`、`CLOCK`、`FF/QRL` 是手工全局共享；可以借鉴机制，但不应将其照搬成新的通用架构。

### 2. 常驻浏览器里的局部运动反馈

```js
preview({ sceneId, shotId, from, to, fps, width });
inspect({ sceneId, times, includeState: true });
patchScene({ sceneId, baseHash, changes });
```

浏览器、字体与资产不应每轮冷启动。改一个模块，热重载这一场景，几秒内回传该镜头的连续运动草稿和状态，再决定是否保留。版本比较固定相同区间、时间点和输出尺寸；恢复旧版本不需重新生成。只有方向成立后再做全片检查和高清编码。完整成片生成→全片审看→整片重写的链路无法提供这样的交互速度。

### 3. 面向画面机制的局部比较与修复

问题必须指向 `sceneId + shotId + objectId + timeRange`：例如“第二次旋转看不出从第一步接续”“原轮廓在移动开始前就消失”“反射点出现但看不出轴对应关系”。候选 A/B 应固定 brief、预算和镜头区间，只改变一种机制。数学状态检查负责角度、位置和组合关系；运动序列审看负责是否可追踪对象、动作与结果。不能用审看者读到意图后复述成功作为质量结论。

十秒“60° 再 60°，与一次 120° 对照”可作为首个基础案例：它同时测试持续对象身份、原位 ghost、角度弧线、组合动作的时间接续及最终叠合。这是 infra 能力验证案例；是否具有参考片水准还需要用户实际观看，不能从测试通过推出。
