# v1：评分前的控制检查和启动失败

本版完成21个控制视频的两版实际渲染，并通过第二次视觉/数值预检。但没有完成任何评分前向。实际推理改在[独立v2](../videoscore-validation-v2/DESIGN.md)进行，同一冻结输入和比较规则保持。

安装：沿用已核验的官方权重和运行环境。模拟：没有模拟模型输出。实际渲染：两个版本各21个视频、1344帧全部解码；第一版终值歧义及不展示闪烁的联系人图保留。模型：官方Codex生成0次，评分权重虽加载成功，本版本前向0次。艺术评价：维护者查看三个概念全部七版本的三时刻联系人图，确认干预；没有总体艺术或学习评分。

按发生阶段保留：

1. 正确行列式刺激在变形中写终值有歧义，v2明确为TARGET。字号25改20并检查长标签宽度，小字仍8；闪烁联系人图改为包含奇数帧。评分前修改，不是看分数后调题。
2. 检查器要求分别H264编码的视频在公式变化前逐像素相同，失败。改为检查编码前原图相同，并保留所有编码后哈希；压缩编码可能改变其他帧，不声称MP4只差文本区域。
3. 首次工具调用在预检失败后仍启动，缺冻结清单立即退出。提交0a660fd标题过早写“冻结”；真正通过记录在2c43504，没有在标题错误时评分。
4. 受限环境看不到GPU；主机实际检查正常。退出发生在模型加载前。
5. 允许访问主机GPU后，模型加载成功，但抽帧输出目录撞上已有控制渲染目录，FileExistsError，第一项未评分、其他35项未执行。旧运行器捕获异常后返回0，保留该行为；退出码不算成功。

新版本只分离评分输出目录，失败返回非零。不更换源视频、提示、数学真值、模型、采样数或事前统计规则。权重、视频、PNG和运行日志在忽略目录。原刺激、通过的刺激、完整失败和冻结哈希可查。本地评分不占官方Codex96次账。
