# 下一轮进度接口对照：设计在调用前冻结

v2 中渐显箭头被当成完整向量检查，且同类 ID 错误多次阻止导出。
修复 SDK 依赖后，原作者源码不变的导出从 10/16 到 14/16，技术通过
仍为 2/16。显式 reveal 的手写正负对照已经实际渲染；这不是模型质量证据。

v3 只检验一个问题：在相同显式进度接口下，确定性检查反馈 C 是否优于
普通自查 B。两者由 Luna 生成，从完全相同的 A 初稿出发，各固定修改一次，
不选最佳版本、不回退、不人工修改候选。A 是初稿、D 是 Astra 一次生成参考。
新的输入数值仍属于已有 Softmax/残差家族，因此只是探索性配对试验。

两个任务 × 两份独立初稿。四组最终候选共 16 条；独立作者请求共 16 次。
每次 common prompt、接口、软源长预算、reasoning、时间上限相同。
B/C 都看到前版作者源码、相同抽帧及执行错误；只有 C 看到检查结果。
前版固定 SDK 文件不再次发送，但本地源码哈希仍含 SDK；减少重复输入不会
被归因于检查反馈。两组实际 tokens 分别记录，不宣称严格同 token 预算。

裁判只看 B/C 两张匿名联系表、问题和四项固定机制要求。每对正反顺序各一次，
共八次审查，全部生成结束后才开始。强裁判结果不反馈给作者。A/D 保留技术
结果和视频，但此轮不为它们赋予模型质量排名。主结论是四次配对 C/B；
反转顺序冲突为未决，缺少视频为不可比较，都不能剔除。旧四项裁判对照仅
作为已有筛查记录，不当成新独立可靠性评测。

全程使用官方已登录 Codex CLI 的现有订阅额度，不购买、不更换付费 API。
模型失败立即停下一批；每批最多四次请求。新一轮外部调用须得到单独的
明确授权，准备、冻结与本地检查先完成。本设计不声称解决作品审美或教学效果。
